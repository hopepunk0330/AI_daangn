# 당근 가격 제안 리디자인 — 디자인 시스템과 프로토타입

중고거래 판매 가격을 AI가 제안할 때, 가격을 **하나의 숫자로 단정할지, 범위로 보여줄지**에 대한 UX 연구의 결과를 당근마켓 가격 입력 화면에 적용한 리디자인입니다. 리디자인에서 나온 값을 **이름 붙인 디자인 토큰**과 **부품 기준**으로 정리했습니다.

- 배포된 프로토타입: https://01-ml-mercari-price-2608.vercel.app/redesign/

## 배경

- 연구 질문: AI 가격 제안을 단일값으로 보여줄 때와 추천 범위로 보여줄 때, 판매자의 가격 결정과 신뢰가 어떻게 달라지는가.
- 데이터: Kaggle Mercari Price Suggestion 데이터로 가격 예측 모델을 만들고, 그 결과를 화면 실험 설계에 연결했습니다.
- 실험: 참여자 화면과 백오피스를 직접 만들어 AB 실험을 설계하고, 이항검정과 Wilson 신뢰구간으로 분석하는 구조를 갖췄습니다.
- 이 저장소는 실험에서 나온 화면 중 **가격 입력 화면의 리디자인**만 다룹니다. 연구 전체는 Mercari 프로젝트 저장소에 있습니다.

## 리디자인 화면 (배포본 기준)

1. **AI 시세 분석 카드**: 최근 동네 실거래 건수, AI 추천 최적가, 동네 이웃의 거래 범위(예: 18,000~22,000원)를 함께 보여줍니다.
2. **추천 거래 범위**: 14,000원부터 27,000원까지의 범위를 막대로 보여주고, 급매·적정 시세·풀박스 위치를 표시합니다.
3. **가격 칩 세 개**: 빠른 거래, 추천가, 상한가를 한 번에 고를 수 있습니다.
4. **키패드 직상단 추천 칩**: 키패드를 열면 바로 위에 추천 가격 칩이 붙어서 한 번에 입력할 수 있습니다.
5. **판매 희망 가격 카드**: AI 최적 단위 일치 여부를 배지로 보여주고, 나눔하기와 가격 제안 받기(네고)를 함께 설정합니다.
6. **등록 완료 팝업**과 **토스트**: 적용과 등록 결과를 짧게 알려줍니다.

## 디자인 시스템

### 구성

```
tokens/tokens.css        디자인 토큰 정의 (단일 출처)
prototype/index.html     토큰을 쓰는 프로토타입
COMPONENTS.md            부품별 용도와 쓰는 토큰
check_tokens.sh          프로토타입에 토큰 밖 색 값이 있는지 검사
qa/                      배포본과 프로토타입을 픽셀로 비교하는 검증 스크립트
```

### 원칙

- 디자인을 새로 정하지 않았습니다. 배포본에서 측정한 값을 그대로 옮기고 이름만 붙였습니다.
- 값은 `tokens/tokens.css`에서만 정의하고, 프로토타입은 토큰 이름으로 참조합니다.
- 토큰 값을 바꾸면 화면이 바뀝니다. 바꾸기 전에 `qa/`로 검증합니다.

### 토큰

| 분류 | 이름 | 설명 |
|---|---|---|
| 브랜드 색 | `--daangn`, `-hover`, `-light`, `-surface`, `--daangn-tint-50/100/200` | 주황 계열 |
| 회색 | `--daangn-gray50` ~ `-gray800`, `--daangn-mute` | 배경과 글자 |
| 보조 색 | `--daangn-purple`, `--daangn-purple-light` | 보라 계열 |
| 중립 색 | `--neutral-white`, `--neutral-black`, `--neutral-50` ~ `--neutral-950`, `--neutral-press` | 흰색, 검정, 회색 |
| 기본 팔레트 | `--orange-50` ~ `--orange-700`, `--purple-50/100/300`, `--blue-100/600` | 배포본이 쓰는 기본 색 |
| 표면·막·글 | `--surface-glass`, `--surface-glass-soft`, `--surface-toast`, `--scrim-50`, `--scrim-40`, `--daangn-ink` | 반투명 표면, 어두운 막, 선택 글자색 |
| 글자 크기 | `--type-micro`(9), `-tiny`(10), `-small`(11), `-caption`(12), `-sm`(14), `-toast`(12.5), `-body`(16), `-lg`(18), `-xl`(20), `-2xl`(24), `-3xl`(30), `-keypad`(22), `-keypad-sub`(8) | px |
| 간격 | `--space-5`, `--space-7` | 자주 쓰는 틈 |
| 모서리 | `--radius-xs`(5) ~ `--radius-2xl`(16), `--radius-full`(999) | px |
| 그림자 | `--shadow-key`, `-float`, `-phone`, `-1` ~ `-4`, `-sm`, `-md`, `-lg` | 배포본 값 |

### Tailwind 연결

- 색과 그림자는 설정에서 토큰을 참조합니다. 색 값을 설정에 따로 적지 않습니다.
- 투명도 클래스(예: `bg-gray-900/75`)가 깨지지 않도록 색 토큰마다 RGB 채널 값(`--이름-rgb`)을 함께 둡니다. HEX 값에서 자동으로 만든 값입니다.
- 글자 크기 클래스(`text-xs` ~ `text-3xl`)는 토큰을 참조하고, 기본 줄 간격을 그대로 유지합니다.
- 임의 값 클래스(`from-[#...]`)는 쓰지 않고 토큰 이름 클래스로 바꿨습니다.
- 이 Tailwind 버전에 없는 그림자 클래스(`shadow-xs`, `shadow-2xs`)는 효과가 없어서 제거했습니다. 화면은 바뀌지 않습니다.

### 부품

부품별 용도와 쓰는 토큰은 [COMPONENTS.md](COMPONENTS.md)에 있습니다. 키패드, 체크박스처럼 상태가 있는 부품은 상태별 모습을 함께 적었습니다.

재현 방법:

```bash
./check_tokens.sh prototype/index.html         # 토큰 밖 색 값 검사
cd qa && npm install && npx playwright install chromium && npm run qa
```

`npm run qa`는 배포본과 `prototype/index.html`을 같은 7개 화면으로 찍어 픽셀을 비교합니다. 차이가 하나라도 있으면 실패합니다.
